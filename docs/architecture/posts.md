# Posts

블로그 게시물의 저작 계약 — 파일 위치·네이밍, frontmatter, 본문 작성, 이미지 정책.

## 1. 파일 위치와 네이밍

- 원고(`.md`)는 `src/posts/content/`에만 둠. `src/posts/` 루트에는 로더 코드만 있음.
- 파일명 형식: `{4자리 순번}-{영문 슬러그}.md` (예: `0001-hello-world.md`). 슬러그는 소문자
  kebab-case 영문.
- 확장자를 뺀 파일명이 그대로 URL id가 됨: `/post/{id}`.
- `src/posts/index.ts`가 `import.meta.glob('./content/*.md', { query: '?raw', eager: true })`로
  전체를 문자열로 로드해 `getAllPosts` / `getPostById`를 제공함.

## 2. frontmatter 계약

파서는 `src/posts/parsePost.ts` (순수 함수, Node 스크립트와 공유 가능).

| 필드          | 필수 | 형식               | 설명                                              |
| ------------- | ---- | ------------------ | ------------------------------------------------- |
| `title`       | O    | 문자열             | 페이지 `<h1>`과 SEO 제목                          |
| `date`        | O    | `YYYY-MM-DD`       | 유효한 날짜. 목록 정렬 기준(내림차순)             |
| `updated`     | X    | `YYYY-MM-DD`       | 실질적 수정일. `date`보다 빠를 수 없음            |
| `description` | X    | 문자열             | 없으면 본문 첫 문단에서 발췌. SEO 설명으로도 쓰임 |
| `category`    | O    | `철학` 또는 `개발` | 태그의 **상위 분류**. 이 두 값 외에는 파싱 에러   |
| `tags`        | X    | `[태그1, 태그2]`   | 없으면 빈 배열                                    |

`category`는 `tags`와 별개의 축임. 허용값은 `parsePost.ts`의 `CATEGORIES`뿐이고, 누락되거나
그 외의 값이면 `parsePost`가 예외를 던짐 — eager 로딩 시점이라 빌드·테스트가 실패함. `/post`
목록의 분류 필터 탭이 이 값을 기준으로 동작함. 같은 값을 `tags`에 중복해 넣지 않음.

`updated`는 본문·구조화 데이터·주요 링크를 실질적으로 수정했을 때만 실제 수정일로 갱신함.
오탈자처럼 의미가 바뀌지 않는 변경에는 갱신하지 않고, 기존 글에 근거 없는 수정일을 일괄
추가하지 않음. 이 값이 sitemap·RSS·JSON-LD에서 쓰이는 방식은
[`routing-and-seo.md`](routing-and-seo.md) §4-2.

## 3. 본문 작성 규칙

- **본문 제목은 `##`(depth 2)부터 시작함.** `#`을 쓰지 않음 —
  `PostDetailPage.tsx`가 `title`로 페이지 `<h1>`을 이미 렌더하므로 `<h1>`이 중복되고, 본문
  `#` 스타일이 페이지 제목과 크기가 겹치며, 목차(`extractHeadings`, 최대 depth 3)의 한 단계를
  소비함.
- frontmatter `title`과 같은 제목을 본문 맨 위에 다시 쓰지 않음. `##`부터 시작하거나 바로
  문단으로 시작함.
- **본문 제목은 `#####`(depth 5)를 넘지 않음.** `MarkdownContent`가 h5까지만 스타일을
  정의하고 h5는 이미 본문(`p`)과 같은 크기라 그 아래로 위계를 더 나눌 수 없음. 원고에
  `######` 이상이 있으면 모두 `#####`로 통일함.

## 4. 이미지 정책

### 4-1. 저장 위치

```
public/posts/<게시물-id>/<이미지-이름>.<확장자>
```

- 게시물별로 폴더를 나눔. 게시물을 삭제하거나 id를 바꾸면 이미지 폴더도 함께 옮김.
- 서빙 경로는 파일 경로와 동일: `/posts/<id>/<이름>.<확장자>`.

### 4-2. 네이밍

- 소문자 kebab-case 영문. 공백·한글·대문자 금지.
- 내용을 서술하는 이름 (`screenshot-1.png`가 아니라 `gradle-build-scan.png`).
- 외부에서 가져온 이미지의 무의미한 파일명(UUID 등)은 저장하면서 개명함.

### 4-3. 본문에서 참조

```markdown
![캐시 적중 시 작업 흐름](/posts/0003-efficient-ci-with-github-actions-jetpack-compose/cache-hit-flow.png)
```

- 항상 `/posts/...`로 시작하는 **절대경로**를 씀. 원고는 `?raw` 문자열로 로드되어 Vite 애셋
  파이프라인을 타지 않으므로 상대경로는 런타임에 해석되지 않음.
- `alt` 텍스트를 반드시 채움.

### 4-4. 외부 이미지 금지

서드파티 호스트의 이미지를 본문에서 직접 링크하지 않음. 내려받아 `public/posts/<id>/`에
저장하고 로컬 경로로 참조함 — 원본이 사라지면 링크가 깨지고, 외부 요청은 방문자 IP를
제3자에게 노출하며, 크기·포맷을 통제할 수 없음.

### 4-5. 최적화

빌드타임 이미지 최적화 파이프라인이 없으므로 커밋 전에 웹에 바로 쓸 수 있는 상태로 가공함.

- 다이어그램·스크린샷은 PNG, 사진은 JPG, 벡터는 SVG.
- 최대 가로 약 1600px, 파일당 300KB 이하를 목표로 함.
- 이미지 총량이 크게 늘면 Git LFS 도입을 재검토함.

### 4-6. SPA 로딩 특성

`public/`의 이미지는 JS 번들에 포함되지 않음. `<img>`가 실제로 렌더되는 시점에만 내려받고
`loading="lazy"`로 뷰포트 근처까지 더 미룸. 이 특성을 유지하려면 이미지를 `import`나
`import.meta.glob`으로 끌어오지 않음 — 그 순간 번들에 포함됨.

### 4-7. 빌드 검증

`scripts/check-post-images.mjs`가 본문의 모든 이미지 참조를 검사하고, 다음 중 하나라도 있으면
빌드를 실패시킴.

- `/posts/...` 절대경로가 가리키는 `public/` 파일이 없음
- `http(s)://` 외부 URL (§4-4 위반)
- `/`로 시작하지 않는 상대경로

## 5. 게시물 삭제

### 5-1. 삭제 절차

1. `src/posts/content/<id>.md` 제거.
2. `public/posts/<id>/` 이미지 폴더가 있으면 통째로 제거.
3. `<id>` 문자열로 `src/`를 검색해 그 게시물을 fixture로 쓰는 테스트가 있으면 다른 게시물로
   옮김.
4. `npm run build`로 sitemap이 해당 URL을 빼고 재생성되는지 확인.
5. 커밋 라벨은 `chore`. `.md` 삭제와 이미지 폴더 삭제를 한 커밋에 묶음.

### 5-2. 순번은 재사용하지 않음

삭제한 순번은 비워 둠. 새 게시물은 항상 현재 최대값 + 1을 씀. 재사용하면 예전 URL을 다른 글이
차지하고 이력 추적이 꼬임.

### 5-3. 이미 배포된 게시물

외부 링크나 검색 색인이 있던 게시물을 삭제하면 프리렌더 대상과 sitemap에서 빠지고 실제 HTTP
404가 됨. 동등한 대체 콘텐츠가 있을 때만 리다이렉트를 검토함.

### 5-4. 비공개는 지원하지 않음

저장소에 남기면서 사이트에서만 내리는 상태는 두지 않음. 저장소가 공개되어 있어 커밋된 원고는
그대로 노출되고, 완성 전 글은 병합하지 않는 것으로 충분함. 비공개로 두려면 해당 `.md`를
저장소 밖으로 옮김.

## 6. 범위 밖

frontmatter `thumbnail` / OG 이미지 — `parsePost`가 읽지 않고 `Seo`의 `override`가
`title`/`description`/`noindex`만 받음. 지원하려면 코드 변경이 선행되어야 함.
